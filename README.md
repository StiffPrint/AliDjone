# АлиДжон Store

Склад, продажи по серийному номеру и касса трёх точек. Самостоятельное приложение Node.js 24.22.1+ со встроенной SQLite; npm-зависимости для работы не нужны.

## Запуск

```sh
export ADMIN_LOGIN=admin@example.com
# Задайте собственный длинный пароль; он нужен только при создании пустой базы.
read -rs ADMIN_PASSWORD
export ADMIN_PASSWORD
export PUBLIC_ORIGIN=http://127.0.0.1:5180
npm start
```

Открыть http://127.0.0.1:5180. SQLite создаётся в `data/warehouse.sqlite`. Другой путь: `DATABASE_PATH`. Администратор добавляет сотрудников с логином (можно использовать email) и паролем от 12 символов. Пароли хранятся как scrypt-хеши. При отключении сотрудника, изменении доступа или сбросе пароля его сессии отзываются. В настройках учётной записи сотрудник может изменить свой пароль.

Менеджер работает только со своей точкой: видит её склад, продажи и кассу, оформляет внесения, изъятия, расходы и переводы из своей кассы. Закупочные цены, себестоимость, прибыль и документы посторонних точек ему недоступны. Входящие перемещения доступны получателю. Общий каталог изменяют администратор и руководитель. Возврат оформляется на точке исходной продажи.

Телефон добавляется в продажу, перемещение, списание или возврат поставщику вводом серийного номера. Сервер проверяет наличие на выбранной точке, статус и уникальность. Аксессуары учитываются количественно и по закупочным партиям FIFO. Списание и возврат поставщику требуют причину. Проведённые документы не редактируются; ошибки продаж исправляются связанным возвратом.

Касса разделяет наличные и оплату картой. Возврат наследует способ оплаты продажи. Доступны начальный остаток (администратор/руководитель), внесение, изъятие, расход и связанный перевод между кассами. Перевод — одна неизменяемая запись: одновременно уменьшает кассу отправителя и увеличивает кассу получателя, не меняя общую сумму денег и прибыль. Изъятие, расход и перевод не могут превышать текущий наличный остаток. Финансы показывают выручку, возвраты, себестоимость, списания, расходы и прибыль за выбранный день или всё время. При неизвестной себестоимости прибыль помечается неопределённой. Это оперативный учёт, не бухгалтерская или налоговая отчётность. На главной странице администратора — три карточки магазинов. Внутри каждой точки доступны её склад, касса и показатели за день. Даты отчётов считаются по Москве (Europe/Moscow); текущие остатки товара и наличных всегда показаны отдельно от исторических остатков кассы на начало и конец выбранного дня.

Данные хранятся по сущностям в отдельных SQL-таблицах, строки документов — отдельно. Сохранение и ключ идемпотентности находятся в одной транзакции BEGIN IMMEDIATE. Все запросы параметризованы. Файл базы и WAL нельзя копировать по отдельности на работающем сервере — используйте команду резервирования.

## Проверки и резервные копии

```sh
npm test
npm run lint
npm run build
npm audit
npm run backup
```

`lint` проверяет синтаксис всех исполняемых JS-модулей. React/TypeScript/Cloudflare scaffold удалён, приложение не использует сторонний JavaScript runtime. Веб-интерфейс проверяется отдельно Playwright (см. `tests/browser.mjs`; пакет инструмента устанавливается вне приложения). Копии SQLite сохраняются в `data/backups`; проверяется integrity_check, сохраняются последние 14 копий. На сервере настроен ежедневный systemd timer.

Для production задайте HTTPS PUBLIC_ORIGIN, HOST=127.0.0.1, PORT и DATABASE_PATH в защищённом EnvironmentFile. Примеры службы и Nginx — в `deploy/`. Не публикуйте исходники, SQLite или файл доступа через Nginx. Автоматическая имитация входа и доверие к заголовкам oai-authenticated-user отсутствуют.

Прежняя облачная D1 и старый локальный JSON не импортируются автоматически. Для явного импорта есть `scripts/import-state.mjs`; импорт выполняется только в пустую SQLite. До открытия базы проверяются цены и количества, ссылки и дубли, роли сотрудников, возвраты, перемещения, партии и соответствие остатков документам. Некорректный снимок отклоняется целиком, существующий склад не перезаписывается. После импорта сотрудникам нужно назначить пароли локальной командой администратора.

Если в импортируемом JSON есть движения аксессуаров из прежнего остатка без документов приёмки, укажите поле `openingBalances`: объект с ID товара и массивом начальных количеств по трём точкам, например `"openingBalances": {"product-id": [3, 0, 0]}`. Начальные количества плюс движения проведённых документов должны совпадать с `balances`. Снимки прежних остатков без движений можно импортировать без этого поля. Неизвестная закупка задаётся `null`, известная цена — целым неотрицательным числом в копейках. При списании прежние остатки аксессуаров без партий расходуются раньше новых закупочных партий, включая последовательные операции после перезапуска.

## Публикация

GitHub Actions выполняет тесты, браузерную проверку и сборку для pull request и push в main. Успешный push в main автоматически обновляет https://alijhone.store с резервной копией и откатом при неудачном запуске. Детали: [deploy/CI-CD.md](deploy/CI-CD.md). Текущий SHA опубликован в `/healthz`.
